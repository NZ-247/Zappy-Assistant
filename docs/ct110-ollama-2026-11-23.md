# Troca conversacional para Ollama no CT 110 em 23/11/2026

## Configuração e recuperação no próximo boot

O `.env` de botadmin recebeu `LLM_PROVIDER=ollama`, `OLLAMA_BASE_URL=http://10.200.48.120:11434`, `OLLAMA_CHAT_MODEL=qwen3:1.7b` e `OLLAMA_CHAT_TIMEOUT_MS=15000`. Antes, as quatro chaves estavam ausentes do arquivo. A conversa usava o padrão OpenAI com `gpt-4o-mini`. O ambiente salvo do gateway já tinha o mesmo endpoint para o modo sombra.

O gateway em dev executa `apps/wa-gateway/src/index.ts` e importa o adaptador, a IA e o schema dos pacotes compilados. Neste ambiente, as chaves existentes no processo prevalecem sobre o `.env`, que prevalece sobre os padrões do schema. O ecosystem define o perfil dev e o dump preserva o ambiente do PM2. Uma verificação com as chaves do snapshot e o loader implantado retornou `restore` para o daemon vazio e resolveu Ollama, modelo, timeout e perfil dev para gateway e API. O modo sombra do gateway continuou ligado. A verificação usou o snapshot e o loader em processo isolado.

Às 18:34, foram reiniciados apenas gateway e API administrativa para recarregar a configuração. O banner do gateway registrou `qwen3:1.7b`; o log registrou `WhatsApp CONNECTED` às 18:34:20.979 com a sessão existente. Às 18:46:54, os cinco processos estavam online, a API autenticada respondeu HTTP 200 sem warnings, e os heartbeats do gateway conectado e do worker tinham respectivamente 5 s e 6 s de idade. Worker, painel e resolver mantiveram os PIDs anteriores. Horários em UTC−04.

## Rollback

Remover do `.env` somente as quatro atribuições adicionadas nesta rodada e executar `pm2 restart wa-gateway admin-api`. O default volta a OpenAI e o snapshot mantém o modo sombra. A cópia anterior do `.env` está em diretório temporário restrito a botadmin, modo `0700`, com arquivo modo `0600`. O procedimento por chaves também funciona sem a cópia temporária e preserva edições posteriores do arquivo.
